# TREC-SAR v0.2.0

**Online radio calibration, the full 3D mission in CI, and a trained thermal detector.**

## Highlights

- **Online radio calibration.** The robot learns the site's radio from the signal-strength readings it already
  gets (Bayesian regression of path-loss exponent and per-terrain attenuation). With a radio 1.8× worse than
  planned, calibrated TREC-SAR reports a casualty 17 min sooner at the median (37 vs 54 min), trips the link-loss
  failsafe 3.4× less often, and uses a quarter of the relays the best baseline needs for the same success rate.
  200 held-out missions per policy, see `results/summary.md`. Run on the live robot with `planner:=trecsar_cal`.
- **3D mission in CI.** Gazebo Harmonic + Nav2 + the mission nodes run on every relevant push. The run passes only
  when the casualty report reaches the command post. Latest: about 330 m driven, drone cue fused, 1 relay,
  1 link-loss recovery, reported at 410 s.
- **Thermal person detector.** YOLO11n fine-tuned on HIT-UAV in CI: held-out test mAP@0.5 0.90, precision 0.88,
  recall 0.88 (579 test images).

## Fixes

The plume decoration fooled the lidar, the lidar was seeing the robot's own relay bay, and skid-steer traction and
Nav2 needed tuning. Full list in `CHANGELOG.md`.

## Still simulation

The radio, detection and lost-person parameters are placeholders. Calibration narrows the radio gap but starts from
them. Nothing has been tested on hardware. See `docs/FAILURE_MODES.md`.
