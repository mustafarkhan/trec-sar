# TREC-SAR v0.3.0

**A corrected benchmark, European radio rules, European scenarios, and reports a command system can read.**

TREC-SAR is an open-source search planner and simulation stack for a tracked rescue ground robot working with a
drone. It plans where to search, where to drop radio relays and when to accept a planned link loss, and it is
scored on the time until the command post receives the casualty report. It is the civilian successor to TREC, a
tracked, reconfigurable UGV developed at NUST for the Government of Pakistan.

## Correction to earlier results

Versions 0.1 and 0.2 reported the benchmark on the one terrain per scenario that the planner was tuned on. On
that terrain link-aware planning looked like a jump from about 40 % to 60 % forest success. **On eight freshly
generated terrains that gap is gone**: all probability-driven policies report 73–74 % of casualties. The benchmark
now holds out terrains as well as casualty seeds, and the old tables are kept in `results/reference_terrain/`.

What holds on held-out terrains (200 missions per policy per scenario):

- **Same success with far fewer relays**: half in the forest and the chemical site, about 70 % fewer in the mine
  tunnel, about a third in the two new scenarios.
- **Planning the link loss matters when the reactive habit breaks**: one relay (62 % → 73–74 %), a radio worse
  than planned (60 % → 68–70 %), the earthquake block (94 % → 99–100 %).
- **Online radio calibration** cuts failsafe trips 3.7× and the median time to report from 47 to 36 min when the
  radio is 1.8× worse than planned.

## New

- **European radio rules.** The video link radiates the 2.4 GHz limit (100 mW e.i.r.p., ETSI EN 300 328). An
  optional 868 MHz telemetry and report link follows ERC Recommendation 70-03 / ETSI EN 300 220: 500 mW at 10 %
  duty cycle or 25 mW at 1 %. The duty cycle sets how long a confirmed report takes on air (59 s or almost
  10 min), and the robot chooses between transmitting and driving back to video coverage. Above ground the link
  removes the supervision problem and most relays; underground it changes nothing. `docs/EU_RADIO.md`.
- **Two European scenarios**, run without retuning the planner: an urban block after an earthquake, and a fire in
  a 1 km twin-bore road tunnel laid out to Directive 2004/54/EC. `docs/SCENARIOS.md`.
- **Standard report formats.** `trecsar run --cap report.xml --geojson mission.geojson` writes a CAP 1.2 alert
  (marked `Exercise` and `Restricted`) and GeoJSON, with ETRS89 coordinates and the national grid (ETRS-TM35FIN
  in Finland, ETRS89 / UTM elsewhere). `docs/REPORT_FORMATS.md`.
- Since 0.1: online radio calibration, the full Gazebo Harmonic + Nav2 mission in CI, and a thermal person
  detector trained in CI on HIT-UAV (held-out test mAP@0.5 0.90).

## Fixed

- Custom sites: overriding one field of a terrain class made the whole class impassable.
- CI runs with a read-only token and verifies the gitleaks download; commit authorship, messages and personal
  notes are checked on every push.
- The licence section now states that Ultralytics YOLO11 and the bundled detector weights are AGPL-3.0.

## Install

```bash
git clone https://github.com/mustafarkhan/trec-sar.git && cd trec-sar
pip install -e "core[viz]"
trecsar compare --scenario road_tunnel --seed 1004 --report-radio eu868_500mw
```

## Still simulation

Radio, detection and lost-person parameters are placeholders. Nothing has been tested on hardware, and TREC-SAR
is not certified for operational use. See `docs/FAILURE_MODES.md`.
